Recipe 20 — Transient & Dynamic Buffers

Geometry the CPU rewrites. A transient buffer for debug shapes rebuilt every single frame, a dynamic buffer for data that changes now and then — the two buffer lifetimes the static createVertexBuffer can't cover.

What you'll learn

  • The three buffer lifetimes — static, dynamic, transient — and when each fits.
  • Allocating and filling a transient buffer with allocTransientVertexBuffer — valid for exactly one frame.
  • The getAvailTransientVertexBuffer guard before you allocate.
  • Creating a DynamicVertexBuffer and rewriting part of it with bgfx::update.
  • Drawing immediate-mode debug geometry — a grid plus an animated ribbon — with a plain coloured program.

Prerequisites

Static vertex and index buffers from recipe 05 and the transform pipeline from recipe 06. We reuse the vs_colored / fs_colored shader style from the early recipes — position plus a packed colour.

Walkthrough

Three lifetimes

Every recipe so far used createVertexBuffer — a static buffer: upload once, draw forever, never touch again. That's perfect for a mesh, and wrong for geometry the CPU keeps changing. bgfx offers two more lifetimes:

  • Static (createVertexBuffer) — immutable after upload. Cheapest to draw, can't be changed. Meshes, the cube, the ground.
  • Dynamic (createDynamicVertexBuffer) — a persistent handle you rewrite with bgfx::update whenever the data actually changes. Good for geometry that's mostly stable but edited occasionally.
  • Transient (allocTransientVertexBuffer) — scratch geometry valid for one frame only. You allocate, fill, submit, and it's gone next frame. Ideal for immediate-mode debug shapes, UI, or anything rebuilt from scratch every tick.

Filling a transient buffer

A transient buffer is carved from a per-frame scratch pool, so it can run out under pressure — always reserve with getAvailTransientVertexBuffer first. Then allocTransientVertexBuffer hands you a struct whose data pointer you write vertices straight into, no staging, no copy. 

struct PosColorVertex { float x, y, z; uint32_t abgr; };

// Rebuild an animated ribbon into a transient buffer, every frame.
const uint32_t kRibbon = 128;
if (kRibbon == bgfx::getAvailTransientVertexBuffer(kRibbon, st->layout)) {
    bgfx::TransientVertexBuffer tvb;
    bgfx::allocTransientVertexBuffer(&tvb, kRibbon, st->layout);

    PosColorVertex *v = (PosColorVertex *)tvb.data;   // write directly
    for (uint32_t i = 0; i < kRibbon; ++i) {
        float u = float(i) / float(kRibbon - 1);
        float x = -6.0f + 12.0f * u;
        float y = 2.0f * bx::sin(u * 12.0f + t * 3.0f);
        v[i] = { x, y, 0.0f, 0xff66ddff };
    }
    bgfx::setVertexBuffer(0, &tvb);                    // note: &tvb, not a handle
    bgfx::setState(BGFX_STATE_WRITE_RGB | BGFX_STATE_WRITE_A | BGFX_STATE_PT_LINESTRIP);
    bgfx::submit(0, st->program);
}
One frame, then gone. You never destroy a transient buffer — bgfx recycles the whole scratch pool at frame(). Allocate it fresh inside SDL_AppIterate every tick; holding the struct across frames is undefined.

A dynamic buffer you update on demand

The ground grid never moves, but we want to be able to change it without recreating the buffer — so it's dynamic. Create it once at the size you need (or hand it initial data), then call bgfx::update only when something changes; in between, it draws exactly like a static buffer. 

// Create once, sized for the whole grid:
st->grid = bgfx::createDynamicVertexBuffer(kGridVerts, st->layout);

// Whenever the grid changes (here: once, at startup), push new vertices:
const bgfx::Memory *mem = bgfx::copy(verts, kGridVerts * sizeof(PosColorVertex));
bgfx::update(st->grid, 0 /*startVertex*/, mem);

// Drawing is identical to a static buffer:
bgfx::setVertexBuffer(0, st->grid);
bgfx::setState(BGFX_STATE_WRITE_RGB | BGFX_STATE_WRITE_A | BGFX_STATE_PT_LINES);
bgfx::submit(0, st->program);

The contrast is the whole lesson: the grid lives in a long-lived dynamic buffer and is uploaded once; the ribbon is reborn into transient scratch on every frame. Neither uses a static buffer, and neither needs a copy pass or a transfer buffer — bgfx hides all of that.

Complete listing

An immediate-mode debug overlay: a wireframe ground grid in a dynamic buffer, and an animated line-strip "oscilloscope" ribbon rebuilt into a transient buffer every frame. The native-handle / loadProgram helpers are from recipe 03 (elided), and the shaders are recipe 05's vs_colored / fs_colored. 

/*
 * bgfx/20-transient-and-dynamic-buffers.cpp — a dynamic grid + a transient
 * ribbon, the two CPU-updated buffer lifetimes.
 * Native-handle + loadProgram helpers identical to recipe 03 (elided).
 * Shaders: vs_colored / fs_colored (recipe 05).
 */
#define SDL_MAIN_USE_CALLBACKS 1
#include <SDL3/SDL.h>
#include <SDL3/SDL_main.h>
#include <bgfx/bgfx.h>
#include <bgfx/platform.h>
#include <bx/math.h>
#include <cstdint>
#include <vector>

static void *nativeWindowHandle(SDL_Window *);
static void *nativeDisplayHandle(SDL_Window *);
static bgfx::ProgramHandle loadProgram(const char *vs, const char *fs);

struct PosColorVertex { float x, y, z; uint32_t abgr; };   // abgr: 0xAABBGGRR

static const int kGridLines = 21;                          // -10..+10
static const uint32_t kGridVerts = kGridLines * 2 * 2;     // two axes, 2 verts/line
static const uint32_t kRibbon    = 128;

struct AppState {
    SDL_Window                     *window = nullptr;
    int                             width = 1280, height = 720;
    bgfx::VertexLayout              layout;
    bgfx::DynamicVertexBufferHandle grid = BGFX_INVALID_HANDLE;
    bgfx::ProgramHandle             program = BGFX_INVALID_HANDLE;
    Uint64                          startNs = 0;
};

static SDL_AppResult fail(const char *what) { SDL_Log("%s: %s", what, SDL_GetError()); return SDL_APP_FAILURE; }

// Fill a grid of lines in the XZ plane (y = 0). Used once to seed the dynamic buffer.
static void buildGrid(std::vector<PosColorVertex> &out) {
    out.clear();
    const uint32_t c = 0xff556070;                         // muted grey-blue
    for (int i = 0; i < kGridLines; ++i) {
        float p = -10.0f + float(i);
        out.push_back({ p, 0.0f, -10.0f, c });             // line along Z
        out.push_back({ p, 0.0f,  10.0f, c });
        out.push_back({ -10.0f, 0.0f, p, c });             // line along X
        out.push_back({  10.0f, 0.0f, p, c });
    }
}

SDL_AppResult SDL_AppInit(void **appstate, int, char *[])
{
    SDL_SetAppMetadata("bgfx Transient/Dynamic", "1.0", "com.example.sdl3.bgfx.buffers");
    if (!SDL_Init(SDL_INIT_VIDEO)) return fail("SDL_Init");

    AppState *st = new AppState(); *appstate = st;
    st->window = SDL_CreateWindow("bgfx — Transient & Dynamic Buffers", st->width, st->height,
                                  SDL_WINDOW_RESIZABLE | SDL_WINDOW_HIGH_PIXEL_DENSITY);
    if (!st->window) return fail("SDL_CreateWindow");
    SDL_GetWindowSizeInPixels(st->window, &st->width, &st->height);

    bgfx::renderFrame();
    bgfx::Init init;
    init.type              = bgfx::RendererType::Count;
    init.platformData.nwh  = nativeWindowHandle(st->window);
    init.platformData.ndt  = nativeDisplayHandle(st->window);
    init.resolution.width  = (uint32_t)st->width;
    init.resolution.height = (uint32_t)st->height;
    init.resolution.reset  = BGFX_RESET_VSYNC;
    if (!bgfx::init(init)) return fail("bgfx::init");

    bgfx::setViewClear(0, BGFX_CLEAR_COLOR | BGFX_CLEAR_DEPTH, 0x0a0e1aff, 1.0f, 0);

    st->layout.begin()
        .add(bgfx::Attrib::Position, 3, bgfx::AttribType::Float)
        .add(bgfx::Attrib::Color0,   4, bgfx::AttribType::Uint8, true).end();

    // Dynamic grid: create once at full size, upload the lines a single time.
    st->grid = bgfx::createDynamicVertexBuffer(kGridVerts, st->layout);
    std::vector<PosColorVertex> gridVerts;
    buildGrid(gridVerts);
    bgfx::update(st->grid, 0, bgfx::copy(gridVerts.data(),
                 uint32_t(gridVerts.size() * sizeof(PosColorVertex))));

    st->program = loadProgram("vs_colored", "fs_colored");
    if (!bgfx::isValid(st->program)) return fail("loadProgram");

    st->startNs = SDL_GetTicksNS();
    return SDL_APP_CONTINUE;
}

SDL_AppResult SDL_AppEvent(void *appstate, SDL_Event *e)
{
    AppState *st = static_cast<AppState *>(appstate);
    if (e->type == SDL_EVENT_QUIT) return SDL_APP_SUCCESS;
    if (e->type == SDL_EVENT_KEY_DOWN && e->key.scancode == SDL_SCANCODE_ESCAPE) return SDL_APP_SUCCESS;
    if (e->type == SDL_EVENT_WINDOW_PIXEL_SIZE_CHANGED) {
        st->width = e->window.data1; st->height = e->window.data2;
        bgfx::reset((uint32_t)st->width, (uint32_t)st->height, BGFX_RESET_VSYNC);
    }
    return SDL_APP_CONTINUE;
}

SDL_AppResult SDL_AppIterate(void *appstate)
{
    AppState *st = static_cast<AppState *>(appstate);
    float t = (float)(SDL_GetTicksNS() - st->startNs) / 1.0e9f;

    bgfx::setViewRect(0, 0, 0, (uint16_t)st->width, (uint16_t)st->height);
    const bx::Vec3 eye = { 0.0f, 9.0f, -16.0f }, at = { 0.0f, 1.0f, 0.0f };
    float view[16], proj[16];
    bx::mtxLookAt(view, eye, at);
    bx::mtxProj(proj, 60.0f, float(st->width)/float(st->height), 0.1f, 100.0f,
                bgfx::getCaps()->homogeneousDepth);
    bgfx::setViewTransform(0, view, proj);

    float ident[16]; bx::mtxIdentity(ident);

    // --- The dynamic grid: drawn straight from its persistent handle ---
    bgfx::setTransform(ident);
    bgfx::setVertexBuffer(0, st->grid);
    bgfx::setState(BGFX_STATE_WRITE_RGB | BGFX_STATE_WRITE_A
                 | BGFX_STATE_DEPTH_TEST_LESS | BGFX_STATE_PT_LINES);
    bgfx::submit(0, st->program);

    // --- The transient ribbon: rebuilt from scratch this frame ---
    if (kRibbon == bgfx::getAvailTransientVertexBuffer(kRibbon, st->layout)) {
        bgfx::TransientVertexBuffer tvb;
        bgfx::allocTransientVertexBuffer(&tvb, kRibbon, st->layout);
        PosColorVertex *v = (PosColorVertex *)tvb.data;
        for (uint32_t i = 0; i < kRibbon; ++i) {
            float u = float(i) / float(kRibbon - 1);
            float x = -10.0f + 20.0f * u;
            float y = 1.5f + 2.0f * bx::sin(u * 12.0f + t * 3.0f)
                           * bx::cos(u * 3.0f - t);
            // Hue ramps along the ribbon so the sweep is easy to read.
            uint8_t r = (uint8_t)(120 + 120 * bx::sin(u * 6.2831f));
            uint32_t abgr = 0xff000000u | (uint32_t(0xdd) << 16) | (uint32_t(0xaa) << 8) | r;
            v[i] = { x, y, 0.0f, abgr };
        }
        bgfx::setTransform(ident);
        bgfx::setVertexBuffer(0, &tvb);
        bgfx::setState(BGFX_STATE_WRITE_RGB | BGFX_STATE_WRITE_A
                     | BGFX_STATE_DEPTH_TEST_LESS | BGFX_STATE_PT_LINESTRIP);
        bgfx::submit(0, st->program);
    }

    bgfx::frame();
    return SDL_APP_CONTINUE;
}

void SDL_AppQuit(void *appstate, SDL_AppResult)
{
    AppState *st = static_cast<AppState *>(appstate);
    if (!st) return;
    if (bgfx::isValid(st->grid))    bgfx::destroy(st->grid);   // dynamic: we own it
    if (bgfx::isValid(st->program)) bgfx::destroy(st->program);
    bgfx::shutdown();
    SDL_DestroyWindow(st->window);
    delete st;
}
No static buffer here. The grid is dynamic and the ribbon is transient, so neither is a createVertexBuffer. The ribbon in particular never lives past frame() — and there's nothing to free for it, which is exactly why transient buffers are the right tool for throwaway, rebuilt-every-frame geometry.

Try it yourself

  1. Turn the ribbon into a CPU particle trail: keep a ring buffer of recent positions on the CPU and dump it into the transient buffer each frame — the same allocate-fill-submit, now driven by simulated points.
  2. Make the grid genuinely dynamic: animate one axis's lines and push them with bgfx::update only on the frames they change. Confirm it draws free on the other frames.
  3. Add the getAvail fallback path: when the guard fails, draw a smaller ribbon (whatever getAvailTransientVertexBuffer reports) instead of skipping it — graceful degradation under scratch pressure.
  4. Draw thousands of debug lines: bump kRibbon hard, or stack many ribbons, and watch the frame stay cheap — per-frame transient geometry is built for exactly this.
