Recipe 19 — Fixed Timestep

Make your physics deterministic and frame-rate independent with an accumulator loop — a constant simulation step, run as many times as the elapsed time demands, and rendered with smooth interpolation in between.

What you'll learn

  • Why integrating raw variable delta time makes physics behave differently at 30, 60 and 144 fps.
  • The accumulator pattern: bank real elapsed time, spend it in fixed-size steps.
  • Keeping a prev and curr state per body and rendering the lerp between them.
  • Clamping the accumulator to dodge the "spiral of death".

Prerequisites

Recipe 04 — Delta Time & Movement. This recipe is the principled upgrade to the variable-dt loop you've used in every recipe since.

Walkthrough

The problem with raw delta time

Every recipe so far multiplied velocity by dt and added it to position. That's fine for simple motion, but the moment physics gets non-linear — gravity, friction, collisions, anything that feeds the result back in — the answer depends on how big each step was. A machine running at 144 fps takes many tiny steps; one at 30 fps takes a few large ones, and the two diverge. Worse, the same replay won't reproduce, because frame times are never identical run to run.

The fix is to decouple simulation from rendering. The simulation always advances by the same constant amount, no matter how fast or slow the frames arrive: 

const double STEP = 1.0 / 120.0;   // simulate at a fixed 120 Hz

The accumulator loop

Each frame, measure the real elapsed time and add it to an accumulator. Then, while the accumulator holds at least one whole STEP, run one simulation step and subtract STEP. Some frames run zero steps, some run several — but each step is always exactly STEP seconds: 

double frame = (now - st->last_ns) / 1.0e9;
st->last_ns = now;

// Clamp before banking: never accept more than 0.25s of debt in one frame.
if (frame > 0.25) frame = 0.25;
st->accum += frame;

int steps = 0;
while (st->accum >= STEP) {
    st->prev = st->curr;          // remember where we were...
    integrate(st->curr, STEP);    // ...and advance one fixed step
    st->accum -= STEP;
    ++steps;
}

Render the in-between with a lerp

After the loop, the accumulator holds a leftover fraction of a step — time that hasn't been simulated yet. If you draw curr directly, motion stutters because that fraction varies frame to frame. Instead, compute an interpolation alpha and draw a blend between the previous and current state: 

double alpha = st->accum / STEP;        // 0..1, how far into the next step

// Render at the interpolated position, not curr.
float rx = st->prev.x + (st->curr.x - st->prev.x) * (float)alpha;
float ry = st->prev.y + (st->curr.y - st->prev.y) * (float)alpha;

This is why we keep both prev and curr: the renderer shows a point partway between the last two simulated states, so the picture is always smooth even though the simulation moves in discrete jumps.

Why clamp?

Drop a breakpoint, drag the window, or hit a hitch and one frame might report half a second. Bank that unclamped and the while-loop owes 60 steps; running them takes longer than a frame, which makes the next frame even longer, which banks even more steps — the spiral of death. Clamping the incoming time (here to 0.25s) caps how far behind the simulation can fall: it simply drops the excess and the game keeps running, a touch behind real time but alive.

Pick STEP for stability, not for looks. Smaller steps (240 Hz) make stiff physics more stable but cost more CPU; the interpolation means the render stays smooth regardless. 120 Hz is a comfortable default for arcade-feel motion.

Complete listing

Three balls bounce inside the window, simulated at a fixed 120 Hz and drawn at interpolated positions so motion stays silky at any refresh rate. The step count run this frame is logged so you can watch it flex as the renderer speeds up and slows down. 

/*
 * 19-fixed-timestep.cpp — accumulator loop with render interpolation.
 */
#define SDL_MAIN_USE_CALLBACKS 1
#include <SDL3/SDL.h>
#include <SDL3/SDL_main.h>
#include "gfx.hpp"

static const double STEP   = 1.0 / 120.0;   // fixed sim rate, 120 Hz
static const double MAXFRM = 0.25;           // clamp: max banked time per frame
static const int    N      = 3;              // number of balls
static const float  RAD    = 16.0f;

struct Ball { float x, y, vx, vy; };

struct AppState {
    SDL_Window   *window   = nullptr;
    SDL_Renderer *renderer = nullptr;
    Ball   prev[N];                 // state at the start of the last step
    Ball   curr[N];                 // state after the last step
    int    w = 800, h = 500;
    double accum = 0.0;
    Uint64 last_ns = 0;
};

/* Advance one ball by exactly dt seconds, bouncing off the walls. */
static void integrate(Ball &b, double dt, int w, int h)
{
    b.vy += 600.0f * (float)dt;            // gravity
    b.x  += b.vx * (float)dt;
    b.y  += b.vy * (float)dt;
    if (b.x < RAD)         { b.x = RAD;          b.vx = -b.vx; }
    if (b.x > w - RAD)     { b.x = w - RAD;      b.vx = -b.vx; }
    if (b.y > h - RAD)     { b.y = h - RAD;      b.vy = -b.vy * 0.92f; }  // floor, slight loss
    if (b.y < RAD)         { b.y = RAD;          b.vy = -b.vy; }
}

SDL_AppResult SDL_AppInit(void **appstate, int, char *[])
{
    SDL_SetAppMetadata("Fixed Timestep", "1.0", "com.example.sdl3.fixedstep");
    if (!SDL_Init(SDL_INIT_VIDEO)) { SDL_Log("%s", SDL_GetError()); return SDL_APP_FAILURE; }

    AppState *st = new AppState();
    if (!SDL_CreateWindowAndRenderer("Fixed Timestep", 800, 500,
                                     SDL_WINDOW_RESIZABLE, &st->window, &st->renderer)) {
        SDL_Log("%s", SDL_GetError()); delete st; return SDL_APP_FAILURE;
    }
    SDL_SetRenderVSync(st->renderer, 1);

    for (int i = 0; i < N; ++i) {
        st->curr[i] = Ball{ 120.0f + i * 120.0f, 80.0f, 130.0f + i * 40.0f, 0.0f };
        st->prev[i] = st->curr[i];
    }

    st->last_ns = SDL_GetTicksNS();
    *appstate = st;
    return SDL_APP_CONTINUE;
}

SDL_AppResult SDL_AppEvent(void *, SDL_Event *e)
{
    if (e->type == SDL_EVENT_QUIT) return SDL_APP_SUCCESS;
    if (e->type == SDL_EVENT_KEY_DOWN && e->key.scancode == SDL_SCANCODE_ESCAPE)
        return SDL_APP_SUCCESS;
    return SDL_APP_CONTINUE;
}

SDL_AppResult SDL_AppIterate(void *appstate)
{
    AppState *st = static_cast<AppState *>(appstate);
    SDL_GetRenderOutputSize(st->renderer, &st->w, &st->h);

    Uint64 now = SDL_GetTicksNS();
    double frame = (now - st->last_ns) / 1.0e9;
    st->last_ns = now;

    if (frame > MAXFRM) frame = MAXFRM;     // clamp: avoid the spiral of death
    st->accum += frame;

    // --- fixed-step simulation ---
    int steps = 0;
    while (st->accum >= STEP) {
        for (int i = 0; i < N; ++i) {
            st->prev[i] = st->curr[i];      // snapshot before stepping
            integrate(st->curr[i], STEP, st->w, st->h);
        }
        st->accum -= STEP;
        ++steps;
    }
    SDL_Log("steps this frame: %d", steps);

    // --- render with interpolation ---
    double alpha = st->accum / STEP;        // 0..1
    gfx::clear(st->renderer, 16, 18, 26);

    const Uint8 cols[N][3] = { {120,200,255}, {255,200,80}, {255,120,180} };
    for (int i = 0; i < N; ++i) {
        float rx = st->prev[i].x + (st->curr[i].x - st->prev[i].x) * (float)alpha;
        float ry = st->prev[i].y + (st->curr[i].y - st->prev[i].y) * (float)alpha;
        gfx::set_color(st->renderer, cols[i][0], cols[i][1], cols[i][2], 255);
        gfx::fill_circle(st->renderer, rx, ry, RAD);
    }

    SDL_RenderPresent(st->renderer);
    return SDL_APP_CONTINUE;
}

void SDL_AppQuit(void *appstate, SDL_AppResult)
{
    AppState *st = static_cast<AppState *>(appstate);
    if (st) {
        SDL_DestroyRenderer(st->renderer);
        SDL_DestroyWindow(st->window);
        delete st;
    }
}

Try it yourself

  1. Add slow-motion: scale the elapsed time you feed the accumulator (st->accum += frame * 0.3) and the whole simulation eases off — the step rate is untouched, only how fast you spend time changes.
  2. Delete the clamp and stall a frame (drag the window, or SDL_Delay(800) once). Log the step count and watch it balloon — that runaway is the spiral of death the clamp prevents.
  3. Raise N to a few dozen balls. The fixed step keeps them all in lockstep, so the simulation stays deterministic no matter the count.
  4. Decouple a slow 30 Hz simulation (STEP = 1.0/30.0) from a 144 Hz render. Without interpolation the motion judders badly; turn the lerp back on and it's smooth again — proof the alpha is doing the work.
