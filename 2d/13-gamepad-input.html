Recipe 13 — Gamepad Input

Drive a sprite with a real controller. Open gamepads as they're plugged in, read sticks and triggers, and handle the dead zone so the thing doesn't drift.

What you'll learn

  • The difference between a joystick and a gamepad, and why you almost always want the gamepad layer.
  • Hot-plugging: opening a controller on SDL_EVENT_GAMEPAD_ADDED and dropping it on SDL_EVENT_GAMEPAD_REMOVED.
  • Reading analog axes with SDL_GetGamepadAxis and normalising them past a dead zone.
  • Edge events (SDL_EVENT_GAMEPAD_BUTTON_DOWN) versus polled state.

Prerequisites

Recipe 03 — Handling Input for the event loop, and recipe 04 for the delta-time movement we reuse here.

Walkthrough

Gamepad, not joystick

SDL exposes controllers at two levels. The raw joystick API gives you whatever axes and buttons the hardware reports, in no particular order. The gamepad API sits on top and maps any recognised pad onto a standard Xbox-style layout — SDL_GAMEPAD_BUTTON_SOUTH, SDL_GAMEPAD_AXIS_LEFTX, and so on — using SDL's built-in controller database. Unless you're building a config screen, use the gamepad layer.

Add SDL_INIT_GAMEPAD to your init flags. You do not enumerate pads at startup and stop there — controllers come and go, so the source of truth is the event stream. 

if (!SDL_Init(SDL_INIT_VIDEO | SDL_INIT_GAMEPAD)) { /* ... */ }

Opening on hot-plug

When a pad appears, SDL posts SDL_EVENT_GAMEPAD_ADDED with the new instance id in e->gdevice.which. Open it with SDL_OpenGamepad and keep the handle. On SDL_EVENT_GAMEPAD_REMOVED, close it. We track a single pad for simplicity — the first one wins. 

case SDL_EVENT_GAMEPAD_ADDED: {
    if (!st->pad) {                              // grab the first one only
        st->pad    = SDL_OpenGamepad(e->gdevice.which);
        st->pad_id = e->gdevice.which;
        SDL_Log("opened: %s", SDL_GetGamepadName(st->pad));
    }
    break;
}
case SDL_EVENT_GAMEPAD_REMOVED: {
    if (st->pad && e->gdevice.which == st->pad_id) {
        SDL_CloseGamepad(st->pad);
        st->pad = nullptr;
    }
    break;
}

The dead zone

Analog sticks never rest at exactly zero — let go and SDL_GetGamepadAxis still reports a few hundred units of jitter. Feed that straight into movement and your sprite drifts forever. The fix is a dead zone: treat anything below a threshold as zero, and rescale the rest so the very first usable input starts at 0, not at the threshold. 

// Raw axis is a Sint16 in [-32768, 32767]. Returns a clean [-1, 1].
static float axis_norm(Sint16 raw)
{
    const float dead = 8000.0f;
    float v = (float)raw;
    if (SDL_fabsf(v) < dead) return 0.0f;
    float sign = v < 0 ? -1.0f : 1.0f;
    float mag  = (SDL_fabsf(v) - dead) / (32767.0f - dead);
    return sign * (mag > 1.0f ? 1.0f : mag);
}

Polled axes, edge-triggered buttons

Two styles, and you want both. Axes are continuous — poll them every frame in SDL_AppIterate with SDL_GetGamepadAxis and integrate against delta time, exactly like the keyboard movement in recipe 04. Buttons are discrete — handle the press once as an event so a tap doesn't register sixty times. 

// Per-frame, in SDL_AppIterate:
float dx = axis_norm(SDL_GetGamepadAxis(st->pad, SDL_GAMEPAD_AXIS_LEFTX));
float dy = axis_norm(SDL_GetGamepadAxis(st->pad, SDL_GAMEPAD_AXIS_LEFTY));
st->x += dx * SPEED * dt;
st->y += dy * SPEED * dt;
Triggers are axes too. The analog triggers report on SDL_GAMEPAD_AXIS_LEFT_TRIGGER / RIGHT_TRIGGER as 0…32767 (one-sided, never negative). We use the right trigger to scale the sprite.

Complete listing

Plug in a controller: the left stick moves the square, the right trigger grows it, and the south button (A / Cross) recolours it. No controller? It opens fine and just sits there until you plug one in. 

/*
 * 13-gamepad-input.cpp — hot-plug a gamepad, drive a sprite with the stick.
 */
#define SDL_MAIN_USE_CALLBACKS 1
#include <SDL3/SDL.h>
#include <SDL3/SDL_main.h>
#include "gfx.hpp"

struct AppState {
    SDL_Window   *window = nullptr;
    SDL_Renderer *renderer = nullptr;
    SDL_Gamepad  *pad = nullptr;
    SDL_JoystickID pad_id = 0;
    float  x = 320, y = 200;
    Uint8  hue = 0;                 // 0..2 cycles the fill colour
    Uint64 last_ns = 0;
};

static float axis_norm(Sint16 raw)
{
    const float dead = 8000.0f;
    float v = (float)raw;
    if (SDL_fabsf(v) < dead) return 0.0f;
    float sign = v < 0 ? -1.0f : 1.0f;
    float mag  = (SDL_fabsf(v) - dead) / (32767.0f - dead);
    return sign * (mag > 1.0f ? 1.0f : mag);
}

SDL_AppResult SDL_AppInit(void **appstate, int, char *[])
{
    SDL_SetAppMetadata("Gamepad Input", "1.0", "com.example.sdl3.gamepad");
    if (!SDL_Init(SDL_INIT_VIDEO | SDL_INIT_GAMEPAD)) { SDL_Log("%s", SDL_GetError()); return SDL_APP_FAILURE; }

    AppState *st = new AppState();
    if (!SDL_CreateWindowAndRenderer("Gamepad Input", 640, 400,
                                     SDL_WINDOW_RESIZABLE, &st->window, &st->renderer)) {
        SDL_Log("%s", SDL_GetError()); delete st; return SDL_APP_FAILURE;
    }
    SDL_SetRenderVSync(st->renderer, 1);

    // A pad already plugged in at launch still arrives as an ADDED event once
    // the loop starts, so there's nothing to enumerate here.
    st->last_ns = SDL_GetTicksNS();
    *appstate = st;
    return SDL_APP_CONTINUE;
}

SDL_AppResult SDL_AppEvent(void *appstate, SDL_Event *e)
{
    AppState *st = static_cast<AppState *>(appstate);
    switch (e->type) {
    case SDL_EVENT_QUIT:
        return SDL_APP_SUCCESS;
    case SDL_EVENT_KEY_DOWN:
        if (e->key.scancode == SDL_SCANCODE_ESCAPE) return SDL_APP_SUCCESS;
        break;
    case SDL_EVENT_GAMEPAD_ADDED:
        if (!st->pad) {
            st->pad    = SDL_OpenGamepad(e->gdevice.which);
            st->pad_id = e->gdevice.which;
            if (st->pad) SDL_Log("opened: %s", SDL_GetGamepadName(st->pad));
        }
        break;
    case SDL_EVENT_GAMEPAD_REMOVED:
        if (st->pad && e->gdevice.which == st->pad_id) {
            SDL_CloseGamepad(st->pad);
            st->pad = nullptr;
        }
        break;
    case SDL_EVENT_GAMEPAD_BUTTON_DOWN:
        // Edge-triggered: one recolour per press.
        if (e->gbutton.button == SDL_GAMEPAD_BUTTON_SOUTH)
            st->hue = (st->hue + 1) % 3;
        if (e->gbutton.button == SDL_GAMEPAD_BUTTON_START)
            return SDL_APP_SUCCESS;
        break;
    default: break;
    }
    return SDL_APP_CONTINUE;
}

SDL_AppResult SDL_AppIterate(void *appstate)
{
    AppState *st = static_cast<AppState *>(appstate);
    Uint64 now = SDL_GetTicksNS();
    float dt = (now - st->last_ns) / 1.0e9f;
    st->last_ns = now;

    const float SPEED = 320.0f;     // pixels per second at full stick
    float size = 40.0f;

    if (st->pad) {
        float dx = axis_norm(SDL_GetGamepadAxis(st->pad, SDL_GAMEPAD_AXIS_LEFTX));
        float dy = axis_norm(SDL_GetGamepadAxis(st->pad, SDL_GAMEPAD_AXIS_LEFTY));
        st->x += dx * SPEED * dt;
        st->y += dy * SPEED * dt;

        // Right trigger is one-sided 0..32767 — grow the sprite up to 2x.
        float rt = SDL_GetGamepadAxis(st->pad, SDL_GAMEPAD_AXIS_RIGHT_TRIGGER) / 32767.0f;
        size += rt * 40.0f;
    }

    // Keep the sprite on-screen.
    int w = 640, h = 400;
    SDL_GetRenderOutputSize(st->renderer, &w, &h);
    if (st->x < 0) st->x = 0; if (st->x > w) st->x = (float)w;
    if (st->y < 0) st->y = 0; if (st->y > h) st->y = (float)h;

    gfx::clear(st->renderer, 18, 20, 30);

    // A little "is a pad connected?" lamp in the corner.
    if (st->pad) gfx::set_color(st->renderer, 80, 220, 120, 255);
    else        gfx::set_color(st->renderer, 200, 70, 70, 255);
    gfx::fill_rect(st->renderer, 12, 12, 14, 14);

    const Uint8 cols[3][3] = { {120,200,255}, {255,200,60}, {255,120,200} };
    gfx::set_color(st->renderer, cols[st->hue][0], cols[st->hue][1], cols[st->hue][2], 255);
    gfx::fill_rect(st->renderer, st->x - size * 0.5f, st->y - size * 0.5f, size, size);

    SDL_RenderPresent(st->renderer);
    return SDL_APP_CONTINUE;
}

void SDL_AppQuit(void *appstate, SDL_AppResult)
{
    AppState *st = static_cast<AppState *>(appstate);
    if (st) {
        if (st->pad) SDL_CloseGamepad(st->pad);
        SDL_DestroyRenderer(st->renderer);
        SDL_DestroyWindow(st->window);
        delete st;
    }
}

Try it yourself

  1. Add rumble on the south button: SDL_RumbleGamepad(st->pad, 0xC000, 0xC000, 200) for a 200 ms buzz.
  2. Support a second player. Drop the "first one wins" guard, store an array of open pads keyed by SDL_JoystickID, and give each its own sprite.
  3. Read the D-pad. It arrives as buttons (SDL_GAMEPAD_BUTTON_DPAD_LEFT …), not an axis — wire them to nudge the sprite a fixed step.
  4. Fall back to the keyboard when no pad is connected, so the demo is always playable. (Recipe 03 has the keyboard half.)
